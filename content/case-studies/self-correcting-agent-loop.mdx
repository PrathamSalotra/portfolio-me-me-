## Problem / Goal

Standard zero-shot code generation models often produce syntactically valid code that fails at runtime due to subtle type mismatches, unhandled edge cases, or incorrect API invocations. Human engineers don't write flawless code on the first try; we run tests, read stack traces, and iterate.

The goal was to build a **Reflexion-based autonomous agent loop** that mimics human iterative debugging—running generated code in an isolated sandbox, analyzing compiler and test stderr, and self-correcting until all assertions succeed.

---

## Architecture Overview

The system pairs an **LLM Code Synthesizer** with a **Deterministic Sandbox Execution Environment** using an event-driven loop.

![Autonomous Self-Correcting Code Generation Loop Architecture](/diagrams/self-correcting-agent-loop.png)

### Iterative Execution Cycle

1. **Synthesis Phase**: The agent receives a problem description and unit test harness, emitting candidate source code.
2. **Sandbox Execution Phase**: Candidate code is mounted into an ephemeral Docker container with network isolation and resource quotas.
3. **Trace Parser Phase**: If exit code `!= 0`, an AST error parser extracts the exact traceback line, failing assertion, and variable state.
4. **Reflexion Engine**: The agent synthesizes a concise reflection note explaining *why* the failure occurred before generating the next candidate patch.

---

## Tech Stack Used

- **Framework**: LangChain (Python) & custom Reflexion memory callbacks
- **Runtime Isolation**: Docker Engine API with gVisor kernel sandboxing
- **Static Analysis**: Python `ast` module, `mypy`, and `pytest-json-report`
- **Model Engine**: OpenAI GPT-4o with structured JSON schema outputs
- **API Service**: FastAPI backend with WebSocket progress updates

## What Broke / Failure Modes Encountered

<FailureModeAlert title="Sandbox Escape Vectors & Non-Deterministic Flakiness" severity="critical">
Early in development, candidate code that spawned background threads or asynchronous event loops would leak processes across sandbox executions. More critically, when tests failed due to race conditions or system clock dependencies, the LLM assumed its logic was flawed and made increasingly convoluted changes to correct a non-deterministic bug.
</FailureModeAlert>

### Additional Failure Modes
- **Error Obfuscation**: Huge multi-thousand-line stack traces from nested frameworks overwhelmed the context window, causing the LLM to fixate on the top of the stack rather than the underlying exception.
- **Overfitting to Test Harness**: The agent sometimes hardcoded return values to satisfy specific unit test assertions rather than implementing general algorithms.

---

## How It Was Fixed / Lessons Learned

1. **Deterministic Error Summarization**:
   - Built an AST-informed traceback filter that strips framework boilerplate and isolates the exact frame where user code triggered the exception.
2. **Strict Ephemeral Sandboxing**:
   - Switched to stateless per-invocation Docker containers with memory limits (256MB), CPU quotas, and zero network access, destroying containers after 10 seconds of runtime.
3. **Anti-Hardcoding Validation**:
   - Introduced a hidden validation test suite that is never shown to the Reflexion loop. Code must pass both public tests and hidden invariants to be marked verified.
