## Problem / Goal

Standard conversational AI agents suffer from catastrophic forgetting: once an interaction exceeds the LLM context window, historical decisions, user preferences, and architectural constraints are lost. Simple RAG pipelines retrieve chunks by static cosine similarity, often surfacing stale or contradictory information from weeks ago.

The goal was to architect a **dual-layer memory engine (Episodic + Semantic)** that incorporates temporal decay, relevance scoring, and automatic memory consolidation for long-horizon autonomous agents.

---

## Architecture Overview

The memory engine separates **Episodic Working Memory** (recent conversational context) from **Semantic Long-Term Memory** (factoids, rules, and historical decisions stored in **Qdrant**).

![Persistent-Memory Long-Horizon Agent Architecture](/diagrams/persistent-memory-agent.png)

### Retrieval & Consolidation Lifecycle

1. **Write Path**: Every turn is evaluated by a lightweight classifier to determine if new factoids or constraints should be committed to persistent memory.
2. **Consolidation Worker**: An asynchronous background cron task merges duplicate entities and resolves contradictory memories using timestamp precedence.
3. **Hybrid Retrieval**: Queries combine dense vector similarity with **Temporal Exponential Decay**, ensuring recent facts outweigh older contradictions.

---

## Tech Stack Used

- **Vector Database**: Qdrant Cloud with HNSW indexing and payload filtering
- **Relational Metadata**: PostgreSQL + pgvector for structured session tables
- **Embedding Pipeline**: `text-embedding-3-large` (1536 dimensions, normalized)
- **Framework**: TypeScript, Next.js Node runtime, LangChain.js
- **Caching**: Upstash Redis for sub-10ms working memory lookups

## What Broke / Failure Modes Encountered

<FailureModeAlert title="Memory Poisoning & Contradiction Drift" severity="high">
During 30-day simulated longitudinal trials, the agent's memory store became polluted with outdated facts. When a user changed their preference (e.g., switching from *Python* to *TypeScript* for a new project), cosine similarity would still retrieve the dozens of older Python memories because they outnumbered the single new TypeScript memory.
</FailureModeAlert>

### Additional Failure Modes
- **Embedding Space Drift**: Upgrading the underlying embedding model rendered existing HNSW vector indexes incompatible, requiring expensive full-corpus re-embedding.
- **Latency Spikes**: Running dense similarity searches on every single conversational turn added 250ms+ latency to the agent response loop.

---

## How It Was Fixed / Lessons Learned

1. **Temporal Decay & Recency Weighting**:
   - Implemented an adjusted score function:  
     **Score = CosineSim(q, v) × e^(-λ Δt)**
   - Recent memories receive a natural boost, allowing new facts to supersede older conflicting records without manual deletion.
2. **Entity-Level Superseding**:
   - Added structured payload tags (`entity_id`, `attribute`, `valid_from`, `valid_to`). When a new value for an entity attribute is recorded, prior entries are marked `superseded: true` and excluded from search.
3. **Asynchronous Memory Indexing**:
   - Decoupled memory writes from the user request loop using background Redis job queues, dropping perceived API response latency from 320ms to 45ms.
